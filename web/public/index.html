What is Dr. ARCSTRA?

Problem: Patient pays upfront, fears treatment won't happen. Clinic treats, fears payment won't come. Both wait, both take risk.

Solution: Money is locked in escrow before treatment. Released only when verified stages complete.

Not a wallet. Not a payment link. A coordination system.
Identity → Agreement → Escrow → Treatment → Verification → Payment

Payment: USDC / USDT / EURC / $SPARKLET. Chain-agnostic design.

Behind the Scenes

1. Economic Finality — One Payment, Once

Each treatment task ends in only one of 4 states: Completed / Rejected / Expired / Invalidated. Only one payment can happen. No double payment.

2. Event Sourcing — Every Decision Replayable

State Layer: current financial truth. Event Layer: immutable history. Every transaction can be rebuilt.

3. Risk Control

Before each release: velocity, amount anomaly, new wallet risk, behavior deviation checked. High risk = no auto-release, human review required.

4. Routing

Best path and chain selected automatically. Targets: Polygon / Sepolia, evolving toward Arc.

Privacy — Medical Data Stays Private

  • X-ray / CBCT / Treatment plan: Off-chain, AES-256 encrypted vault.
  • Only SHA-256 hash goes on-chain. Hash proves existence, reveals nothing.
  • GDPR Art. 17: Right to be Forgotten = Delete key, data becomes unreadable.
  • Patient controls who sees what. Clinic sees treatment, not wallet history.

No HIPAA claim. GDPR / KVKK aligned design, legal review ongoing.
